# Release workflow for Barend's own signed APK

Phase 1 ([plan](https://github.com/bflutz/nytka-server/blob/phase1/docs/voice-recorder-plan.md), §5). Barend installs his own build (via Obtainium or by hand), not upstream's APK, because the phase-1 changes exist only in this fork.

**Change:**
- Adapt `.github/workflows/release.yml` (or add a new workflow), triggered by a tag `bflutz-v*` on this fork.
- It builds `assembleOssRelease`, signs with a keystore from repository secrets (`SIGNING_KEYSTORE_B64`, `SIGNING_STORE_PASSWORD`, `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD`; names only, Barend adds the secrets), and attaches the APK plus its SHA-256 to a GitHub release.
- Use an applicationId suffix or a different package name, so it can't clash with an upstream install.
- Put the steps to make the keystore and add the secrets in `docs/how-to/own-release.md`.

**Done when:**
- Without the secrets, the workflow fails with a clear message and no unsigned upload.
- The workflow validates (actionlint).
- Upstream's release workflow doesn't run on this fork's tags.
- Note: changing `.github/` is allowed for this issue.

Heads-up: GitHub's Actions token can't push changes under `.github/workflows/`, so the HQ builder may not be able to push this one. If it can't, Barend does it by hand or the builder puts the file elsewhere for Barend to move.
